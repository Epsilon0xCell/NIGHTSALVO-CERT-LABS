# Lab: Log triage, find the spray

- Track: CompTIA Security+ (SY0-701)
- Objective mapping: Domain 4, Security Operations: log data sources,
  alerting and monitoring activities, incident response basics.

## Scenario

`auth.log` holds one morning of SSH traffic on a bastion host. The
help desk has one vague ticket: "someone was knocking on the server
last night." They are right, and one account on this box is no longer
yours. Your job is to find the intrusion in the noise and report it
precisely enough that someone else can act on it.

The log is synthetic and generated by `gen_log.py` (seeded, so the
file in this folder is the file the generator makes). All addresses
are in documentation ranges.

## Setup

Nothing to build. You need the log and standard text tools, or
Python. Work in this folder so the grader finds your answers.

## Tasks

1. Identify the external address that carried out a password spray
   against this host.
2. State how many failed password attempts came from that address.
3. State which account the attacker finally got into.
4. State the timestamp of the attacker's first attempt, in the same
   format the log uses (for example `Oct 14 04:05:20`).

Watch out for the decoy: more than one external address failed a few
logins that night. Volume and outcome separate them.

## Answer format

Create `answers.txt` in this folder:

```
attacker_ip=<ip>
compromised_account=<account>
failed_attempts=<count>
first_seen=<timestamp>
```

Then run `python3 grade.py`.

## Hint ladder

1. Do not read 219 lines one at a time. Count first, read second.
2. Group the failures by source address and sort by count. Then ask
   the log a second question: which of those addresses ever has an
   Accepted line?
3. The `uniq -c` and `sort -nr` combination on extracted fields is
   the classic shape for this. The Security+ materials on log
   analysis cover the same workflow.
