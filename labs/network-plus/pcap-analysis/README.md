# Lab: Packet capture analysis

- Track: CompTIA Network+
- Objective mapping: Domain 5, Network Troubleshooting: packet
  capture analysis, TCP connection behavior, common service ports.

## Scenario

`capture.pcap` is a short capture from a workstation segment: sixteen
frames. Two DNS lookups, one TLS-looking flow, and one plain HTTP
exchange. The HTTP response carries a reference code the support team
needs, formatted as a `SALVO{...}` flag, but the response did not
arrive in one piece and the pieces did not arrive in order. Reading
the capture in raw frame order will not give you a readable page.

The capture is generated by `gen_pcap.py` (stdlib only), and
`pcap_lite.py` is a small pcap reader that ships with the lab: it
prints a flow summary, and with `--streams` it reassembles TCP
payloads by sequence number. tshark or Wireshark will also open the
file, and following the TCP stream there is the same operation the
parser performs.

## Setup

Nothing to build. Python 3 runs both tools.

## Tasks

1. Produce the flow summary and identify every distinct conversation
   in the capture: protocol, endpoints, ports.
2. Identify which flow is the HTTP exchange and which host and port
   served it.
3. Reassemble the HTTP response in sequence order and recover the
   reference code.

## Answer format

No grader. The flag is the reference code itself, in `SALVO{...}`
form, recovered from the reassembled response body.

## Hint ladder

1. Sixteen frames is few enough to list completely. Start with the
   summary, not the payloads.
2. TCP does not promise arrival order; it promises sequence numbers.
   Any tool that follows a stream is sorting segments by sequence
   before joining them.
3. The Network+ troubleshooting materials cover the capture workflow:
   summary, filter to one conversation, then follow the stream.
